      Makes a replica physically unable to commit an authoritative side effect.

      Wraps the INSTALLED surface rather than a known list, so a capability added later is refused until somebody classifies it. That direction is the safe one: an unclassified capability costs a failover to the primary, where an unclassified capability waved through costs a divergent site.

      A refusal throws before the inner function is called, which is what makes the primary retry safe.

      Parameters

      • binary: Record<string, unknown>

        The instantiated PHP module, mutated in place.

      • OptionalonRefusal: (refusal: ReplicaRequiresPrimary) => void

        Called with each refusal before it is thrown; the caller uses it to record the failover.

      • Optionalcollect: (statements: readonly string[], payload: unknown) => void

        Turns SQL refusal into forwarding. Given one, a mutating transaction is downgraded to the driver's speculative path -- replayed, read through, rolled back -- and its statements are handed here for the primary to commit. Only SQL forwards: a mutating capability is an outbound effect like mail, and there is no rollback for one that has been sent.
