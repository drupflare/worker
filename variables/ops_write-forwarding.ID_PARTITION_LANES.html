    Variable ID_PARTITION_LANESConst

    ID_PARTITION_LANES: 32

    The lane count every residue class is computed against.

    A CONSTANT, NOT THE POOL SIZE, because no lane could learn the pool size and the partition was therefore absent on every deployed pool. idPartition() read REPLICA_COUNT from env, which the canonical wrangler.jsonc does not set, so a real lane was configured lanes = 0; the driver takes $lane >= 1 && $lanes >= 1 as false and strides on nothing. The whole disjointness property -- the thing that makes a forwarded id safe to re-send on a conflict retry -- was unreachable in production while its unit tests passed on a hand-set REPLICA_COUNT.

    Fixed at replicaCount's own ceiling, so the stride is 33 and lanes 1..32 hold distinct non-zero residues however many exist. Nothing has to be told the count, which is the point: a lane cannot read the primary's lanes_provisioned at all, because cfw_meta is replica-local by design and is deliberately not copied.
