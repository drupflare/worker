      The change counts for a declared file set, before any bytes have been sent.

      planSync() CANNOT ANSWER THIS AND THE FIRST VERSION ASKED IT TO. It compares by SOURCE, so a file whose blob has not been uploaded yet has no source to compare and has to be left out of its input -- at which point planSync sees a path that is stored and not incoming and calls it REMOVED. Every modified file in an upload reported as a removal, which is the opposite of what it is, and the route's own comment claimed the missing ones were "counted as incoming".

      Counted directly instead, and the missing source is not needed: a declared file whose blob the site does not hold carries bytes the site has never seen, so it is added when the path is new and modified when it is not. Only a path whose blob IS held can be unchanged, and only then by comparing the two sources.
